# Casa — интерфейс оценки квартиры (лендинг + визард): дизайн

Дата: 2026-07-26
Статус: утверждено, готово к написанию плана реализации

## Контекст

Полное ТЗ и бизнес-логика описаны в `../../../SPEC.md`. Этот документ — дизайн
первого куска интерфейса: публичный лендинг и мастер оценки квартиры для
продавца. Бэкенд ещё не реализован (Фаза 1 из SPEC.md не начата), поэтому
интерфейс строится на типизированном mock-слое данных, который позже
подменяется на реальные API-вызовы без переписывания компонентов.

Явно вне скоупа этого захода: авторизация, личный кабинет со статусом сделки,
подписание договора/ЭЦП, каталог для покупателя, показы, CRM-панель. Это
следующие этапы по плану из SPEC.md.

## Флоу

Выбран гибридный вариант: низкий порог входа на лендинге (только адрес),
детали — на отдельной странице.

1. **`/` (лендинг)** — hero с полем ввода адреса, блок «как это работает»
   (объяснение двух цен), блок доверия/кейсов (заглушка), футер. Сабмит адреса
   ведёт на `/otsenka?address=...`.
2. **`/otsenka` (мастер оценки)** — пошаговый интерфейс без перезагрузки
   страницы (client-side state), четыре шага:
   1. **Подтверждение адреса** — mock-слой сопоставляет введённый адрес с
      известным домом/ЖК (по образцу данных из Airtable: ЖК Prime Garden,
      Жошы хана 27, Есиль) и показывает карточку найденного объекта. Если
      сопоставления нет — fallback: ручной выбор района из списка.
   2. **Параметры квартиры** — комнатность, площадь (м²), этаж / этажность
      дома, состояние ремонта (свежий ремонт / хорошее жилое / косметический /
      требует ремонта).
   3. **Результат** — две карточки цены:
      - «Срочная продажа» = базовая рыночная стоимость × **0.90**
      - «Рыночная продажа» = базовая рыночная стоимость × **0.93**
      Визуально «рыночная» подана как более крупная/акцентная (выгоднее по
      цене), «срочная» — с акцентом на скорость (иконка/подпись про сроки).
      Отдельное состояние: «Данных пока недостаточно» — приглушённый, не
      тревожный стиль (жёлтый/серый бейдж), если по объекту мало аналогов —
      соответствует реальному состоянию в исходных данных Airtable.
   4. **Контакты** — показывается только по клику «Продолжить» на шаге
      результата: имя, телефон, чекбокс согласия на обработку персональных
      данных → экран подтверждения «Мы с вами свяжемся».

## Визуальный стиль

Направление: современный тех-стартап, не редакторский минимализм Casavo.

- **Шрифт:** геометричный sans-serif (класс Inter/Manrope), хорошая
  поддержка кириллицы
- **Акцентный цвет:** зелёный (ассоциация «деньги / рост»), на светлом
  нейтральном фоне (не чистый белый), текст — тёмно-серый/почти чёрный
  (не чистый `#000`)
- **Компоненты:** карточки с крупным радиусом скругления (16–20px), мягкие
  тени, много воздуха между блоками
- **Иерархия на экране результата:** карточка «рыночная продажа» визуально
  доминирует (крупнее/акцентнее) как более выгодный вариант; «срочная» —
  вторична, с явным акцентом на скорость сделки
- **Состояния неуверенности данных** — визуально отделены от ошибок: не
  красный/тревожный, а приглушённый нейтральный стиль с понятным пояснением

Токены (цвета, отступы, радиусы, типографика) фиксируются как Tailwind-конфиг
на этапе реализации.

## Технический подход

- **Стек:** Next.js (App Router) + TypeScript + Tailwind CSS
- **Данные:** typed mock-модуль с двумя функциями:
  - `matchAddress(input: string)` — имитирует серверное сопоставление адреса
    с иерархией район → ЖК → дом (по образцу реальных данных из
    Casa Airtable System)
  - `calculateValuation(params)` — считает `instant` (×0.90) и `market`
    (×0.93) цены от базовой стоимости, включая состояние «недостаточно
    данных»
  Обе функции спроектированы с сигнатурой, совместимой с будущим REST/GraphQL
  API, чтобы замена на реальный бэкенд не требовала переписывания компонентов.
- **Демо-адрес:** «Жошы хана 27, ЖК Prime Garden, Есиль» — из реальной
  выборки Airtable, чтобы флоу можно было пройти end-to-end на осмысленных
  данных.
- **i18n:** только русский язык в этом релизе, без инфраструктуры
  мультиязычности (казахский/английский — в будущем).
